# Vantage Company Architecture adapter v0

Status: design only, 2026-10-25. Inspected source: `83cf88c8aa77b33587632a0b352f6365275d0153` on the isolated feature checkout. No adapter is activated, no profile is rebuilt, and no Vantage v1 or Joseph/Sophia V0 interface is amended by this document.

The smallest proposed adapter reads the existing canonical company profile, preserves its fact provenance, checks every dependency against the requesting actor, and supplies one bounded `RequiredCompanyArchitectureSourceV0` through the existing V0 ports. It does not generate Company Architecture, resolve business roles, retrieve additional documents, or make another model call. The profile is a candidate source for that contract, not proof that the product's definition of Company Architecture is already fulfilled.

## Task 2 implementation follow-up — 2026-10-25

The original audit and recommendations below describe source `83cf88c8aa77b33587632a0b352f6365275d0153`. The subsequent authorized implementation starts from `98c8eaeca1606e86e638a815c408410e735fe141` and adds the opt-in pure [`projectCompanyArchitectureV0`](../../pipelines/src/vantage/context-v0/company-architecture.ts), with a separate server reader/guard seam. This does not activate the default generation path.

- The proposed review gate below was a recommendation, **not an existing V0 contract requirement**. The implementation always emits `reviewState: "unreviewed"`; it creates no approval workflow, receipt store or automatic `unknowns-marked` transition.
- `available` means the actor-authorized projection is safe and useful under its declared source/field/budget checks. It does not mean human approval or a complete `RequiredContextBundleV0`. Identity plus a substantive authorized fact is the minimum; extra declared required paths add to it. Missing optional organizational fields remain explicit unknowns.
- A `partial` projection may provide safe canonical content for registry inspection, but withholds `requiredEntry`. It cannot silently satisfy mandatory Company Architecture coverage. Joseph/TL retain ownership of final review policy, required-field policy and the complete mandatory bundle.
- All positive document dependencies, including grouped subject identities, must be authorized and exactly current before their fused value is exposed. Manual entries remain unreviewed accounts. Profile/provenance/version and actor/ACL identities bind the projection; current-state guards must recheck them before use or persistence.

The stricter whole-source/review activation recommendations in the original proposal are therefore not claims about the implemented default behavior. See the implementation's focused synthetic tests for its actual boundary; production activation remains separate work.

## Proposed read-only mapping

Resolve identity and scope on the server. Read the exact company's metadata row and relevant `company_profile_sources`/document-version metadata in a consistent database snapshot. Use the schema table directly for the narrow missing canonical fields rather than changing a public profile DTO. Keep bigint identifiers as decimal strings; reject unsafe legacy numeric identifiers rather than rounding them.

| V0 field                                                           | Proposed mapping                                                                                                                                                                                                            |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source.kind`, `source.id`, `source.companyId`, `source.canonical` | `company`, stable singleton locator `company-metadata/<companyId>`, authenticated company ID, `true` only after the canonical-profile ownership decision below. Include the actual row ID in the internal fingerprint.      |
| `source.version`                                                   | `company-profile-v0:<sha256(canonical snapshot)>`, using the version recipe below; never `schemaVersion`, `facts_hash`, `builtAt` or model name alone.                                                                      |
| `source.reviewState`                                               | Explicit review policy/receipt below. Default `unreviewed`; never infer approval from a build or confidence.                                                                                                                |
| `companyId`, `access`, `aclDigest`                                 | Authenticated company; `allowed` only after dependency checks; digest produced from server-resolved current membership/document policy and the dependency access decisions. A payload-supplied digest is not permission.    |
| `audience`, `required`, `canonical`                                | Existing contract requires `{kind: "company", companyId}`, `true`, `true`. This is source metadata; the manifest/report remains actor-bound and grants no company-wide sharing.                                             |
| `sourceDate`, `checkedAt`                                          | The latest relevant canonical/source/edit timestamp no later than `reportWindow.asOf`; actual authorization-check time. Never backdate a post-cutoff current row.                                                           |
| `excerpt`                                                          | Deterministic bounded text of included fact paths/values, trust labels, exact source versions and quotes, followed by explicit unknowns/staleness. Only complete fields; no silent truncation that changes a qualification. |
| Registry `content`, `contentHash`, `provenance`                    | The exact authorized serialized content and its SHA-256; connector `company-metadata`, internal canonical locator and adapter version. Do not invent a public citation URL or offset.                                       |

Start with a declared field allowlist: company identity/description, services, markets, projects, policies, relevant organizational roles and explicit profile facts. Do not copy arbitrary `derived_views`, email/phone fields or all legal text by default. A person's recorded `people.role` is descriptive context, not the requesting actor's business-role mapping or any permission grant. Missing strategy, responsibilities or priorities remain unknown; do not synthesize them from a company name.

Only active, temporally applicable facts that pass the existing confidence/manual-override gate are candidates. Preserve the distinction between an extracted account, model synthesis and a human-entered value. `manual_override` records what an authorized person entered; it does not prove that work happened or that the entire profile was reviewed. `visibility` and `usage` fields are handling labels, not document ACL or external-delivery authorization.

## Multi-document permission and provenance rule

Before constructing any excerpt, collect **all** backing documents of every candidate value, including quote-less dependency records retained beyond the synthesis excerpt cap. Query them with `scopedDocumentWhere(companyId, scope)` and repeat `scopeAllows` on returned rows. Missing, deleted, cross-company or denied rows fail closed. Never authorize a fused value merely because its first citation, one quote or one contributing document is visible.

Use the stricter all-dependencies rule for ordinary merged facts as well as synthesized fields. Do not reuse the permissive ordinary-fact display behavior as a model boundary. Do not expose a hidden document's title, quote or ID in omission messages. A manual value with `doc_id: 0` is a separate company-profile assertion; it has no verified document citation.

For each document-backed assertion, validate the stored exact version/snippet relationship and source-reader state. Legacy missing versions must remain unverified; do not attach today's version to an old quote. A changed document or an indexed version is not proof that a task, milestone or acceptance check completed. A source row that is stale/failed/pending can retain old facts in today's producer, so `isCounted` alone is insufficient freshness.

Proposed initial activation policy: if a required architecture dependency is unavailable, return unresolved mandatory context with no excerpt/evidence snapshot; do not silently call an authorized subset the complete canonical architecture. A future partially visible architecture policy needs an explicit contract/product decision. This conservative choice preserves one canonical source version across actor scopes and avoids relabeling a personalized view as a company-wide artifact.

## Canonical versions, cutoff and revalidation

Serialize with sorted object keys, explicit nulls, decimal bigint IDs and ISO timestamps; retain meaningful array order and sort source dependency sets by exact document/version/snippet identity. Hash:

- Adapter/projection version and canonical metadata row identity, DB/JSON schema versions, complete semantic fact records and provenance, including all source refs, visibility/usage/status/confidence, edits and synthesis dependencies.
- Relevant source-row facts/status/override/reader/model/version identity and timestamps; exact document/version/snippet identities and content fingerprints where verifiable.
- The explicit review receipt and its version, including acknowledged unknowns. Keep volatile `checkedAt` out of the content version; freeze current access and ACL digest separately.

[`factsHash`](../../pipelines/src/company-metadata/assemble.ts) hashes normalized active path/value pairs for summary caching. A source quote/version, ACL, confidence or manual-review change can leave it unchanged; it is not this adapter's fingerprint. `company_metadata_history` stores diffs and can omit no-diff saves, so it is not sufficient to reconstruct an exact historical full profile. If only a newer current profile exists at an earlier requested cutoff, report unavailable/stale context until an exact retained snapshot is supplied; never pretend the current row was valid then.

Put the exact source version into `ContextManifestV0.companyArchitectureVersion` and `sourceVersions`, with the canonical registry content hash bound into the evidence snapshot and `ContextFreezeV0`. Preserve the existing actor/company/window/ACL bindings. Implement `ServerContextPortV0.currentState` for this source from fresh server reads, and use existing [`captureFreeze`, `assertFreezeCurrent`, `commitContextGeneration`](../../pipelines/src/vantage/context-v0/adapters.ts) before invocation, after invocation and inside persistence. Any content, provenance, review, source-version or authorization drift invalidates the result; no cached hidden excerpt is a fallback. A frozen snapshot is not permission to reopen it later.

Budgets must be passed explicitly through existing `ContextBudgetsV0`. Bound native reads and total work, honor cancellation, and account for backing document entries as well as the company excerpt. A required source that cannot fit is an explicit blocked/omitted result, not a successful empty architecture. Do not increase the current generation budget or invoke profile extraction/synthesis to fill a gap.

## Explicitly reviewed means a recorded review

No current canonical schema field records whole-profile approval. Source override `about_us` only confirms inclusion; a manual fact edit confirms that one entered value. Model confidence, quote checks, `roleBy`, build `ready` and `facts_hash` are not review receipts.

Before using `reviewed` or `unknowns-marked`, the owning module must supply a server-verifiable receipt bound to the exact architecture/projection version, reviewer identity, review time, authorized scope, reviewed fields and acknowledged unknowns. `reviewed` means that review occurred, not that every claim is infallible. `unknowns-marked` requires an explicit approved policy and actual unknowns, not an automatic downgrade that bypasses review. Revisions invalidate an older receipt unless that policy explicitly covers them. Without this capability the source stays `unreviewed` and the proposed adapter must not mark its required bundle complete. This document creates no receipt store, approval UI or mutation.

## Remaining dependencies and acceptance tests

Activation remains blocked on: a named owner accepting `company_metadata` as the canonical architecture input and defining its required fields; version-bound review receipts and the `unknowns-marked` policy; safe actor/ACL digest and exact-version readers; the source's transactional `currentState` implementation; retained historical-snapshot policy; approved finite adapter budgets; and a context-aware generation/persistence integration. Joseph still owns role/required-context resolution and Sophia owns dynamic retrieval; this adapter must not implement either module. Personal stars, mandatory documents and public research remain unchanged and independently permission-checked.

Required synthetic tests before activation:

1. Single-source exact version/quote maps deterministically; reordered DB rows produce identical canonical versions. Meaningful value, provenance, reader, review or source-version changes invalidate them; timestamp-only permission checks do not change content identity.
2. Multi-source fused facts with one denied/deleted/cross-company source reveal no value or source metadata. Include a restricted thirteenth synthesis dependency beyond the quote cap and a first-visible/second-hidden ordinary fact.
3. Absent actor scope, revoked membership, changed folder/group grants and forged actor/ACL values fail before model invocation; repeat revocation during generation and immediately before persistence/readback.
4. Legacy missing `version_id`, unsafe numeric IDs, stale/failed/pending source rows, invalid validity ranges, future edits/extractions and a post-cutoff canonical row cannot acquire invented current provenance. No available historical snapshot means explicit unavailability.
5. Model confidence 1, `about_us`, build-ready status and an unrelated manual edit cannot produce `reviewed`; valid receipts, mismatched version receipts, missing reviewer/time and explicit acknowledged unknowns exercise the agreed policy.
6. Manual `doc_id: 0` assertions remain human-entered accounts, deprecations/reset behave honestly, and names/roles never grant ACL or business-role privileges.
7. Excerpt/source/query/token/time limits and cancellation preserve omissions and block unresolved mandatory context. The reader never calls rebuild, extraction, retrieval, public research or a second model.
8. Real PostgreSQL with synthetic companies verifies scoped reads, canonical serialization, concurrency invalidation and preservation of existing profile/history/report rows. V0 registry/assembler/freeze tests and frozen V1 response/compatibility regressions remain green.
